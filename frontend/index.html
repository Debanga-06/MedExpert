METHODOLOGY

Facts in. Explanation out.

Five deterministic stages — no training data, no hidden weights beyond what's listed here.

01

Symptoms

You select what you're experiencing from a fixed, defined list — nothing free-text, nothing ambiguous.

02

Facts

Each selection is converted into a discrete fact — fever = true — that the engine can reason over.

03

Knowledge base

Every disease is a hand-written rule: required "core" symptoms, optional supporting symptoms, and a weight.

04

Forward-chaining engine

Facts are matched against every rule. A rule "fires" the moment at least one of its core facts is present.

05

Ranked, explained result

Matched weight ÷ maximum weight = rule-match score. Every result names the exact rule that produced it.

Example rule

Rule R001 · Influenza
IF   fever AND cough AND fatigue         (core)
AND  body_pain, chills, headache …        (supporting)
THEN possible_disease = Influenza
     score = matched_weight / max_weight × 100

ABOUT THIS PROJECT

An expert system, built to be inspected.

Objective

Demonstrate a traditional rule-based AI expert system — knowledge representation, forward-chaining inference, and explainable output — as a learning project, not a clinical tool.

Stack

  • Frontend — HTML / CSS / JS, WebGL via three.js
  • Backend — Python, FastAPI, Pydantic
  • Reasoning — custom forward-chaining rule engine
  • Interface — REST API + CLI

What this is not

Not a diagnostic tool, not trained on patient data, not reviewed by a clinician, and not a replacement for professional medical advice at any point in the flow.
